fix: `anet node start` 把 pi-cli 派到 Claude 车道（claude: command not found）
版本: 2.3.0-preview.193 / 2.5.0-preview.156（成对 tgz，不发 npm）
分支: pixb
前置: 34ae46b3（create 选择器漏 pi-cli，.192/.155）

一、现象
  节点创建正确了（runtime=pi-cli），但启动时：
    anet node start 3-agent-network-pi
    [anet] Starting new session for "3-agent-network-pi" [pi-cli]...
    /bin/sh: line 1: claude: command not found
    [anet] ⚠ Your Claude Code CLI does not advertise --session-id. ...
    [anet] ❌ NODE_CHILD_PID_MISSING

二、根因
  launchAgent 里「这个 runtime 交给 agent-node 还是启动器自己 spawn claude」
  的判据又是一张**手写 runtime 枚举**（claude-agent-sdk / codex-sdk /
  codex-app-server / grok-build-acp / grok-build-cli / opencode-cli），
  没有 pi-cli → 直接落进 claude-code-cli 分支 → 本机没有 claude CLI → 子进程
  pid 缺失。与 34ae46b3 的 create 选择器漏项是同一类错误：两处手写枚举。

三、修法
  · src/normalize-runtime.ts 新增表驱动的
      AGENT_NODE_RUNTIMES = SUPPORTED_RUNTIME_NAMES - ["claude-code-cli"]
      launchesAgentNode(runtime)
    claude-code-cli 是唯一「启动器自己 spawn claude」的车道，其余全部交给
    agent-node。bin/cli.ts 的手写 if 链换成 launchesAgentNode(runtime)。
  · 新增 resolvePiAgentNodeLaunchPlan()：对能探到的候选（ANET_AGENT_NODE_BIN
    / standalone 内置 / 旁边那份 sibling）用 planSupportsRuntime(plan,"pi-cli")
    验证；老 agent-node 会在启动前被拒，而不是静默跑成别的 runtime。
    PATH / npx 兜底路径维持原样。
  · 回归测试（src/normalize-runtime.test.ts）：pi-cli 必须走 agent-node；
    唯一的 launcher-owned runtime 必须是 claude-code-cli。

四、验证（Docker 内）
  tests/test725-agent-node-unit-ci    3111 pass / 3 skip / 0 fail  RESULT: PASS
  tests/test745-agent-network-unit-ci 2197 pass / 13 skip / 0 fail RESULT: PASS
  agent-network tsc --noEmit rc=0；normalize-runtime.test.ts 45 pass

  真机（本机，hub 192.168.1.3:9200）：
    源码：bun agent-network/bin/cli.ts node start 3-agent-network-pi
          → runtime: pi (input: pi-cli)，已注册到 CommHub，SSE connected
    打包件：/tmp prefix 安装 .193/.156 后同样 → runtime: pi，SSE connected
    （分别用源码与 tgz 各跑一次，均无 claude 车道痕迹）
