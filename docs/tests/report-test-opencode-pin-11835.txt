## 三、为解锁验证而修的上游腐化（窄变更，均与 pin 无关的既有坏）

1. `tests/test386-.../Dockerfile`: 补 `COPY agent-node/src/runtime/capacity-retry.ts` —— 合并 #2451(board656) 后 runtime.ts 引 `../capacity-retry`，cherry-pick 式 COPY 未跟上 → 镜像内 module not found，套件从未跑到深处。
2. `tests/test386-.../run.sh`: fixture 重写 `node -e` → `bun -e` —— oven/bun:1.3.1 镜像的 node 是 fallback wrapper：`-e` 参数被吞、未捕获异常仍 exit 0 → 空 mktemp 被 mv 覆盖 fixture package.json（0 字节）→ exact-bin 候选版本校验必败，报成 "entrypoint is outside node_modules"（errors[0] 是 /test/bin 老 shim 的干扰信息）。bun -e argv 正确、行为已实测。
3. `tests/test384-.../run.sh`: 常量派生 sed → bun -e import（#902 修过 test386，test384 漏改；常量现为 `= PAIRED_AGENT_*` 派生，sed 恒空）。
4. `tests/test384-.../wizard_probe.py`: 菜单标签 `codex-app-server` → `codex-cli`（#1139 改显示名）+ 顺序对齐 createRuntimeChoices（9/25 owner 决策 grok-build-cli 垫底）。
5. `tests/test-rfc029-pr1-registration/run.sh`: 转义正则漏网 `1\.18\.34` → `1\.18\.35`（全局字符串替换打不中反斜杠形态）。
6. 本机环境：host bun 1.4.2 的 `bun install` 把 gitignored 的 `agent-network/bun.lock`/`agent-node/bun.lock` 重写为 lockfileVersion 2，被 oven/bun:1.3.1 套件 COPY 后 bun install 直接报 Unknown lockfile version。两文件已移至 /tmp/opencode-diff/*.bak（可再生、不入库；CI 无此文件不受影响）。**注意：以后在本仓跑过 bun install 后、再跑 bun:1.3.1 基底套件前需删掉 bun.lock。**
