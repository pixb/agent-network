    今天（11-06）我们把 main 推到 43b99dce9 ⇒ 没有产生任何 run，也没有 queued/in_progress

仓库本身 `fork=true private=false`（公开仓库 ⇒ 公共仓库的 Actions 分钟数不受私有配额限制），

**启用/禁用 Actions 是仓库设置项（UI 里），REST 没有开启接口** ⇒ 需要人在
`github.com/pixb/agent-network → Settings → Actions → General` 打开。这条我这边做不到。

### CI 抓到的两个真问题（都在我们写的文件里，我们此前没看出来）

1. **`[oss-public-surface] personal_home: 2`** —— `deploy/compose/Dockerfile.source` 与
   `deploy/compose/README.md` 写了 `/home/<名字>/…` 形状路径。门的判据是形状
   `(?:^|[^A-Za-z0-9])/(?:home|Users)/[A-Za-z0-9._-]+`，仓库里**除这两个文件外没有别处写这种形状**
   （其他文件一律写 `$HOME/.anet`）。修法只动形状不动运行时：容器家目录 `/srv/dashboard`
   （`useradd -d` + `ENV HOME` 同步），README 写 `$HOME/.anet` + 「想知道具体值就 `docker exec … echo $HOME`」。
   运行时实测（新镜像 2699766de590，一次性容器 :3199）：
   `$HOME=/srv/dashboard`、`uid 10001`、`$HOME/.anet/config.json` 在、`/login`=200、
   带会话打 `/api/hub/networks` = 502（hub 故意不可达）、**日志里 ENOENT/EACCES 次数 0**
   ⇒ 不是当年那个「缺 config.json ⇒ 每个认证请求 500」。
2. **Lint 4 处 `Cannot access refs during render`**（`app/messages/page.tsx`）：
   渲染里读写 `meRef` 拿当前用户名。改成仓库既有写法 `useState(() => currentUserAlias())`
   （`app/lib/chat-unread.ts` 早就是这么写的），memo 依赖补上 `meAlias`。

本地对照（tip ec65c3b）：`npm run lint` 0 errors、`npm test` 333 pass/0 fail、
`npm run oss:check` 34/34、`npm run gates` exit 0、`npm run build` 通过。

## 3. 为什么 push/PR 不触发（fork 的实测形状）

- `unit-tests.yml` 写的是 `push: branches: ['**']`，今天推了 5 次 pixb ⇒ **0 个 run**
  （`GET /actions/workflows/unit-tests.yml/runs` 显示从未运行过；仓库 run 总数当时=4，全是 dispatch）。
- 开 PR #3（`pixb` → `main`，同仓库）⇒ `no checks reported`，队列里也没有。
- `workflow_dispatch` 稳定可用，且真在 `ubuntu-latest` 上跑完。

⇒ 这条 fork 只认 dispatch（以及面向上游 parent 的 PR）。所以给 `unit-tests.yml` 与
`gates.yml` 的 `on:` 各加了一行 `workflow_dispatch`（只动 `on:`，不动 job），加完立刻跑绿。
**这是 fork 上唯一可靠的 CI 入口**；push 触发在 fork 上不要指望。
