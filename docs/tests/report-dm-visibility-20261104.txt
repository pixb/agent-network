4. 一次性 hub 实测的通道落点（skill 仓 tests/manual_node_scenario.sh）
════════════════════════════════════════════════════════════════════════
每条都在 throwaway hub 上真跑（注册真实用户 + 真实节点 token），读回真实 REST：

  通道                       落表                                   Dashboard 页面
  ─────────────────────────────────────────────────────────────────────────────
  send_task                  tasks + inbox                          Tasks / Messages
  report_status              sessions                               Nodes
  reply --via send_reply     inbox(session_name=派单人用户名) +      Messages
                           tasks.result
  reply（默认 =              completions + tasks.result             只有 Tasks 页；
  report_completion）                                              Messages 与收件箱都没有，人无未读
  dm（send_desktop_message） user_inbox(kind=agent_message)          /messages/inbox
  say（send_message）        inbox(session_name=节点别名)            Messages

关键实测细节（不是文档推论）：
  - 默认 `reply` 跑完后 `SELECT ... FROM inbox` 全程只有派活那一条行；私信表
    user_inbox 为空。→ 「report_completion 发了，Dash 上看不见」是落表形状，
    不是投递失败。
  - `--via send_reply` 后同一文本出现在 `?alias=<用户名>` 与 `?tasks` 的 result
    里；`?scope=user` 里没有。
  - `dm` 后同一文本出现在 `?scope=user` 里、`?alias=` 里没有；任务保持 running，
    下一轮任务照常投递进节点 inbox。
  - 人类账号没有 sessions 行 → `say <用户名>` 必然 alias_not_found；`dm` 用
    to_username，节点 token 即可发。
  - 人↔人私信（/api/dm，kind=human_dm）发件人固定为鉴权用户名，且拒绝 dm_to_self。

自动化结果：

5. 约定（写进 skill，供派活方与节点双方遵守）
════════════════════════════════════════════════════════════════════════
1. 指挥室是用户账号，不是节点。派活用 utok/atok；不要给 manager 建节点
   （report_status 拒用户 token，人也没有 sessions 行可投递）。
2. 拓扑 B 方案：每项目一个 network；节点别名带机器+项目；utok 无隐式网络，
   读接口一律带 ?network_id=。
3. 中途提问用 `dm <用户名>`（任务保持 running，人收到未读）；回答即交付用
   `reply --via send_reply`（进消息流）；纯收尾用默认 `reply`（只有 Tasks 页可见）。
   提问绝不写成 reply：send_reply/report_completion 都是终态，replied 不在
   retry_task 接受集合里。
4. 派活显式写 ttl_seconds（默认 3600s = 一小时；上限 86400）；retry_task 只续
   1 小时，长跑的活重新派。COMMHUB_STALE_OPEN_TASK_HOURS 默认 0（生产未设置），
   它管的是「开工后静默」，不替代 TTL 决定；要启用需评审后改 ~/.commhub/hub.env。
5. 残留节点清理：`anet node delete` 先删本地目录再删 hub 行，hub 半边失败会只
   留 warning；用 `anet node delete <node_id> --hub-only` 重试。本次删掉
   n_bec69957（manager）与 n_e73e4164（30-pix-auto-video-opencode）后，
   nodes 4→2，tasks/inbox/completions 不受影响（DELETE 级联只动 nodes/sessions/
   team/requirement 引用）。
