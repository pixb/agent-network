## 实机测量（hub API 读回，逐条）

| task_id | 正文长度 | delivered | running(started_at) | replied |

| `649f3979-eef3-4c66-9ef3-75a4704c42a4`（对照） | 117 | 18:28:43 | 18:28:43 | 18:29:00 |

三条都走通 `delivered → running → replied`，用时约 17–20 秒。
关键机制在 hub：`working` 那一步要**逐字**匹配正文
`UPDATE tasks SET status='running', started_at = datetime('now') WHERE to_name = ?1 AND status IN ('delivered','acked') AND content = ?2`
（`server/src/tools.ts:1492-1493`），而节点上报的是它从 hub 取回的正文 ⇒ **长度不影响这一匹配**（三条实测都命中）。

顺带纠正我自己的一个读法错误：REST 任务行**没有 `acked_at` 字段**（字段是
`delivered_at / started_at / runtime_submitted_at / consumed_at / completed_at`）。我一开始打印
`d.get("acked_at")` 得到 `None`，写成「acked_at 为 null、逐字回传没落地」——那是**字段不存在**，不是没落地。
按 `started_at` 读才算数（本轮已改口径）。

## 新规则（skill v0.7.0，§1.2a）

- **brief body**（无 payload 文件）：≤1200 字符，第 1 行 ≤80 自足，**必须有 `accept:` 块**，
  markdown-safe（空行分块、`- ` 列表、`key: value`；禁表格 / `#` / `**` / 反引号）
- pointer body 保持：规格超过一个参数、需要 `sha12` 证明、需要在 git 里评审、跨轮复用时用它
- 机械判据：`bash scripts/anet_payload.sh guard --body "…" --kind brief`
  （实测一对：1200 收 / 1201 拒；删掉 `accept:` 拒；加表格拒）

派给 `3-agent-network-pi` 的演示正文（484 字符，dashboard 的任务面板会渲染成列表）：

```text
演示任务：只读汇报本节点的环境，不写盘不联网
purpose: a formatted task body the task pane renders as a list

steps:
- pwd
- git rev-parse --abbrev-ref HEAD
- git rev-parse --short HEAD
- node --version, and say so if it is unavailable

accept:
- the result names the branch, the commit sha and the node version
- the result lists each command you ran, in the order you ran it

deliverable: the result text only, nothing written to disk
report_completion once, result <= 1200 chars, line 1 is the conclusion
```

节点到货 641 字符，里面自己用了 markdown 表格与反引号 —— 任务面板渲染正常，
Tasks 详情页（纯文本面）会露出 `|` 与反引号。**这正是 skill 把版式按面定的原因**，
也是 dashboard 那条 issue 的内容（`docs/issues/dashboard-task-delivery-plain-text.md`，未提）。
