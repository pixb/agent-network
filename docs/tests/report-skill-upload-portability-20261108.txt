## 2. dispatcher 侧：`anet_payload.sh upload`（B）

```bash
ANET_TOKEN=… bash scripts/anet_payload.sh upload --file commhub_tasks/r07/spec.md \
    --hub "$COMMHUB_URL" --network <network_id> --name spec.md --mime text/markdown --allow-untracked
#   uploaded: commhub_tasks/r07/spec.md (5123 bytes) -> file_id 3c63099f0bf34bf398708698da2decaf
#   sha12: 54b3cd5aa536
#   put on the pointer line:  attachment: 3c63099f…  sha12: 54b3cd5aa536
#   and in the dispatch:  meta.attachments = [{type:"file", file_id:"3c63099f…", …}]
```

三条设计（都是实测出来的）：

- **12 MiB 在本地拒**，一个字节都不上网络：exit 3，消息里带字节数和上限。
- **access string 只从环境读**（`ANET_TOKEN`），**故意不做成命令行参数** —— argv 在 `ps` 和 shell 历史里可读；
  header 通过 curl 的 stdin config（`-K -`）传进去。缺 token 直接拒并点名 `ANET_TOKEN`。
- 未入 git 的文件要 `--allow-untracked`（明说"我要走 hub 这条路，不是分支"）；**`dirty` 在这条路上不拒**，
  因为字节随附件走，sha12 钉住是哪一版（git 那条路才拒 dirty：工人拉的是分支，不是你 working tree）。

## 3. 跨网络 404 从代码阅读变成实测

`tests/manual_node_e2e.sh` 现在注册第二个用户（自带 network）、在**那个网络**里 init 节点，然后取第一个网络上传的文件：

```
node of network net_76067d43492f cannot read the file uploaded in net_d5a2d90e0b45 (hub answers 404, not 403)
```

断言三件事：非零退出、走 404 那句话、**不落任何文件**。同一轮 e2e 还断言：13 MiB 被拒、缺 ANET_TOKEN 被拒、
`bad_attachments`、`files`、取回字节逐字节相同、错 sha12 exit 3 且不落文件、未知 id 404。

## 4. 两条规则进闸门 —— 以及一条被撤掉

eval spec 加了两条命令型判据。`guard-refuses-absolute-path` 两个 runner 都绿；
**`guard-counts-characters-not-bytes` 撤掉了**，理由是实测到的自相矛盾：

| 运行方式 | 结果 |
|---|---|
| `run_pipeline.py`（含 holdout） | 84 checks，**0 failed** |
| 验证器 rollout（`generate_verification.py`） | 77 checks，**11 failed**（7 个 val case 全红在这条上） |

根因：这条判据量的是 **python 的解码默认**，不是脚本的计数 —— CJK 正文要经过 `python3 -c` 管道，
文本编码随环境 locale 变，而验证器在剥了环境的情况下跑。它在量主机，不在量协议。
撤掉（子模块 `c59ca66`），并把原因写进 `wiki/patterns/portable-protocol-content.md`：
**量到 runner 环境的闸门比没有闸门更糟**，它会因协议管不着的原因大声失败。

正解留给下一轮（已写进 pattern，未实施）：`guard --json` 自己同时报**字节数**与**字符数**，
判据变成一个程序内的算术比较，管道里没有 locale 依赖。

撤掉之后：`run_evals.py --rollout --include-holdout` = **72 checks, 0 failed, 0 errored, 0 regressions**。
