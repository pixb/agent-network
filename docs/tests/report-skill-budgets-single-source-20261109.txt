3. 三条理由被测量改掉（不是改口味）
────────────────────────────────────────────────────────────────────────
  a) context「≤200 因为预览切 200」是错的：Dashboard 不渲染 task.context
     （TaskChatPanel.tsx / TaskDetail.tsx 从不读它），hub 接受 10000。
     context 的真实成本是 worker 的上下文 ⇒ 400，一行写完。
  b) 任务面板的 ≈12 行折叠（COLLAPSE_MAX_PX = 300，TaskChatPanel.tsx:601）是
     「展开全文 ⌄」按钮后面的折叠，不是永久遮蔽（:634-637）。
     ⇒ 交付正文的硬规矩是顺序：第 1 行结论、第 2–12 行证据、之后逐条验收、长报告落文件；
       不是「1200 以内才看得见」。
  c) 真正的悬崖是 hub 只存前 4000 字符（result/output 都是）。2400 是留余量，
     任何 >4000 的交付会被静默截断，所以 4000 写进 budgets.json 的 hard_constraints。

────────────────────────────────────────────────────────────────────────
4. 被否掉的一条提案（写明理由，避免下次重提）
────────────────────────────────────────────────────────────────────────
  否：给 CJK 正文加 1.5–2× 字符系数（即中文正文按更宽的字符预算算）。
  理由：hub 的 zod 上限与存储截断都按 JS 字符数计；预览也是盲切字符数；
        CJK 约 1 token/字符，2× 字符数＝2× token 成本，且 Dashboard 拉丁宽度界面里中文是全宽。
  做法：预算继续按字符计；guard 输出 cjk 占比与 est_tokens 估算，让写正文的人自己看见代价。
  实测样例（本轮的演示正文）：575 字符，CJK 217（38%），est_tokens ≈ 306。

5. 纪律变成默认（不再依赖人记得加旗标）
────────────────────────────────────────────────────────────────────────
  - 每个正文都必须带 accept: 要求行（原来只有 brief 与「引用任务 id 的改派」强制）；
    引用任务 id 的 --kind task 正文会被点名是改派，要求改用 --kind resend 审。
  - markup 默认拒绝（表格行 / # 标题 / **加粗** / 反引号）；--no-markup 退役为告警，
    显式旗标改成 --allow-markup。
  - brief/result 自动做版式检查：行长 ≤120、`- ` 项目符号、ASCII `key: value`、无制表符。
  - compose 机检 ttl ≥ 2× 节点 idle 预算（hub 不检查这条：默认 3600，上限 86400）。

10. 追加（同日）：指针正文 360 → 480（skill v0.7.4）
────────────────────────────────────────────────────────────────────────
  运营口径：指针正文可以扩容字数吗？当前 360。答复：可以，改一处（scripts/budgets.json），
  门 budgets-in-docs-match-the-script 保证文档与脚本不漂移 ⇒ 已落 480。

  为什么是 480，不是更多（三条墙，按测量排）：
    1) 显示墙（Dashboard）：sessions.task 只留前 200 字符（盲切），节点卡片 line-clamp-2
       ⇒ 指针的第 1 行 + 第 2 行前半可见；第 3 行起在派工人看的面上不可见。
    2) 每轮成本墙：指针正文每派一次活就进一次 worker 上下文，480 字符 ≈ 480 token/轮/工人
       （CJK 约 1 token/字符，guard 直接打印 est_tokens）。
    3) 纪律墙：正文写长了，人就懒得落 payload 文件；不落文件就没有 sha12，
       就没有「worker 干的是哪一版」的可验证性（sha12 的作用是防止干到旧版）。
  不是墙的两件事（写明，避免下次又当成理由）：
    - hub 上限：接受 10 000 字符，宽裕；
    - 逐字节回显（report_status: working）：长度不破坏翻转，现网 484 字符正文实测走过
      delivered→running→replied。
  ⇒ 480 的依据是模板实测：4 行中文指针 213 字符，加一行 context 的最坏现实形状 271 字符，
     480 留 209 字符富余；360 只留 89。再往上（>600）在派工人看的面上完全不可见，纯付 token。
  需要同样的富余去写步骤 → 用 brief 正文（≤1600，任务面板渲染成列表）或落 payload 文件。
