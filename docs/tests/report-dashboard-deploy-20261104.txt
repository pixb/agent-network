```bash
# 0) 回滚件：先给现网镜像打标签，覆盖标签前必须有这一条
docker tag <现网 image id> anet-dashboard:rollback-20261104

# 1) 构建：在 dashboard 仓库，按 parent 套件的镜像标签打（部署身份 = 已提交且已推送的 pixb）
cd /vol1/1000/docker/nec8-docker/agent-network-dashboard
git status --porcelain                     # 必须为空
REV=$(git rev-parse HEAD)                  # 71c895c…
docker build -t anet-dashboard:compose \
  -f deploy/compose/Dockerfile.source --build-arg SOURCE_REV="$REV" .

# 2) 起：在 parent 仓库，只动 dashboard 服务，不重建、不碰 hub
cd /vol1/1000/docker/nec8-docker/agent-network/deploy/compose
docker compose up -d --no-build dashboard
```

顺序里两处是刻意的：**先提交再构建**（label 才对应得上镜像内容，本轮此前踩过两次），
**先打回滚标签再覆盖标签**（`anet-dashboard:compose` 这个标签被覆盖后，旧镜像只剩有名字才找得回）。

## 5. 部署过程中量到的三件事（都是本轮之前不知道的）

1. **源码构建镜像缺 `$HOME/.anet/config.json` 会让每个认证请求 500。**
   现网装包路径早就在镜像里预置了这份文件，源码构建路径没有；直接部署必 500。
   已在 `Dockerfile.source` 补齐（内容只有中性 hub 默认地址，无 token 无主机名），
   并把「预置存在 + `ENV HOME=` 写死 + 不含 token/真实主机」三条做成契约门。
2. **compose 5.5 在旧容器名占用时会把新容器命名成 `<短id>_anet-dashboard-1`。**
   本轮第一次 `up` 就出现该名字，引用 `anet-dashboard-1` 的 runbook/脚本会失效。
   处置：`docker rm -f <前缀名>` 后再 `up -d --no-build dashboard`，名字回到 `anet-dashboard-1`。
3. **`--no-build` 是必需的显式声明。** 换的是镜像标签，不是构建定义；
   带构建的 `up` 会按 parent 的 `Dockerfile.dashboard`（npm 钉版本）重建，
   把刚部署的 pixb 镜像换回 preview.56 —— 静默换版本正是这类部署最难的故障。
