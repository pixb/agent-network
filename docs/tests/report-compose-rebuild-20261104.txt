0. 本轮定义（写进仓库根 AGENTS.md）
----------------------------------------------------------------------
- pixb = 我们自己的生产分支，只在本地部署；main 只作为上游同步分支，

----------------------------------------------------------------------
1.1 dashboard 不是 pm2，是 compose 容器：
    docker ps → anet-dashboard-1  镜像 anet-dashboard:compose  宿主 3200 -> 容器 3000
    docker inspect → 项目 anet，network anet_default，无挂载（无状态），

    端口对照：:3200/login=200、:3000/login=404（:3000 是 gitea，登录路径 /user/login）

1.2 「最新代码有没有上线」= 没有，三条独立证据：
    :3200/login 自报 0.6.3-preview.56
    :3200/messages/inbox = 404（与 /messages/xxxnotexist 同形）
    POST :3200/api/hub/messages-ack = 404；对照 POST /api/hub/messages|tasks|health = 405
    → 405 表示路由存在且不接受该方法的；404 表示路由不存在。

1.3 版本链落差（npm registry 实测 1030 个版本）：
    生产 :3200          0.6.3-preview.56
    npm preview 标签    0.6.3-preview.60
    origin/main         d722a34 = release 0.6.4-preview.345 → registry 404，从未发布
    origin/pixb         main + 4 提交（7468ccb 6207a11 28cb5ac b84d315）
    结论：发布链在本次变更之前就已断一截；新模型把这条路关掉。

1.4 hub 实测：
    anet-hub-1  镜像 anet-hub:compose（oven/bun:1.4.0 + COPY server/）
    bind mount deploy/compose/data -> /data（commhub.db 7.27M + wal + backups + hub.env 0600）
    healthcheck = bun -e fetch('/health')，5s/5s/20s/30 次（容器里没有 curl）

3. hub 重建演练（tests/compose-rebuild/rebuild-drill.sh，全在隔离资源上）
----------------------------------------------------------------------
构建标签 anet-hub:drill（绝不覆盖现网 anet-hub:compose）、端口 19323、
一次性 vault 密钥与一次性数据目录，不读 data/、不读 data/hub.env。
  ok: 构建通过（COPY server/bun.lock + bun install --frozen-lockfile）
  ok: label 记录源码提交 = b546e84eb20a8bce280b7963ed0345103768f071
  ok: 缺 vault 主密钥被 entrypoint 拒绝启动（fail-closed 实测）
  ok: /health = 200
  ok: 镜像自带 healthcheck 判为 healthy
  ok: 自报版本 0.9.0-preview.265
演练第一遍跑挂过两次，两次都是定义里没写的事实，已写进 README：
  a) 不设 HOST/PORT 时服务绑 loopback，发布端口打不通 → compose.yaml 里显式给
     HOST=0.0.0.0 + PORT=9200（桥接网络形状，与 pm2 路径的 127.0.0.1 契约不同）
  b) bind mount 的数据目录必须能被容器 uid(1000) 写。docker 自动建的目录是
     root owned，hub 在 bun:sqlite 建库时抛异常，日志只看到 `at new Database`，
     看不出是权限问题 → README 写明 `mkdir -p data && chmod 777 data`

5. 数据与恢复边界（写进 README，避免误以为 clone 即拥有生产数据）
----------------------------------------------------------------------
- dashboard 无状态：用户/token/任务/消息全在 hub 侧 SQLite。
- hub 数据 = deploy/compose/data/（bind mount /data），不入 git。
- data/hub.env 是 vault 主密钥（0600）。恢复必须用**原值**：
  现场新生成 64 hex 解不开既有密文，那不是恢复，是把数据变成砖。
  entrypoint 对此 fail-closed。
