## 3. 评估出的问题（用户口径：skill 必须通用，不得针对单一项目）

P1 单项目/单机耦合（最严重）
- 12 个 `evals/golden/case-*/input.json` 全部写死
  `"hub_source": "/vol1/1000/docker/nec8-docker/agent-network/server"`，v0.6.0 新增的
  `case-12` 继续复制；`tests/manual_node_e2e.sh:21` 直接
  `bun run /vol1/1000/docker/nec8-docker/agent-network/server/bin/commhub.ts`
  ⇒ 闸门只在「源码恰好在那个路径的那台机器」上成立。
- 示例文本绑死某内容项目的某一轮（"第7轮 seg-01：头三段配图，3 张暖金佛像特写入库"），
  出现在 SKILL.md、README.md、references/payload-files.md、references/manual-node.md 和两个测试里。
- 绝对路径守卫枚举自家挂载点：`*/home/*|*'/vol1/'*|*'~/'*|*'C:\'*`
  （`scripts/anet_payload.sh`、`tests/manual_node_scenario.sh:575`）。

P2 与自己脚本自相矛盾
- §1.1 说"一轮最多一个 commhub 调用，脚本不豁免"，而 `scripts/anet_manual_node.sh` 的
  `working` 一条命令打 3–4 个调用（`get_task` + `ack_inbox` + `report_status` + `get_task`，
  `scripts/anet_manual_node.sh:604-640`），`reply` 打 2 个；§7.4 第一句
  "Every command in §7 is a commhub call, so it is one round" 按字面是假的。

P3 说过头的句子
- "A 4-line pointer fits inside [the 200-char preview]"：实测默认正文 258 字符，
  前 200 字符切在第 3 行，第 4 行整行被切。
- "`report_completion` 是一次性的，所以一批 report 哪个都不生效"：三条各自带
  `task_id` 的 report 三条都落；真正落不到的是把多任务塞进一个 `task=` 串。
- `wiki/skill-impact.md` 给两条 2026-11-07 的 proposal 记 `Held-out validation score: 1.0000`，
  而其唯一证据 `raw/2026-11-07T192707Z-66718fafa7e2.json` 只有一个步骤
  `validate the eval spec`；分数来自 `wiki_maintenance.py --validation-score`（人工传入，工具不算）。

P4 脚本鲁棒性
- `die()` 把退出码打进消息：实测 stderr `the file has no segment seg-09 2`、
  `… do not guess 3` ⇒ 按句子写断言必然打不中。
- 字符预算用 `${#…}` 量，非 UTF-8 locale 按字节计：同一正文 UTF-8 下 257、
  `LC_ALL=C` 下 293（中文 ≈3×）⇒ 守卫会在合法正文上拒，且打印数字随 locale 漂。

## 4. 修复（v0.6.1，子模块提交 `647909d` 行为 + `49bd12f` 证据）

- 通用性：12 个 golden input 删掉 `hub_source`；hub 源码解析顺序
  `ANET_E2E_HUB_SRC`（可指 `server/` 或 repo 根）→ 相对 skill 目录
  （`<repo>/.agents/skills/agent-network-skill` → `../../../server`）→ `$PWD/server` →
  `$HOME/agent-network/server`；e2e 不再硬编码路径。示例全部换成中性内容（补单元测试 + 更新文档），
  文档里的 sha12 用脚本真跑出来的值（`3f7c64c57fb6` 等）。绝对路径改成按形状判定
  （token 以 `/`、`~/`、`X:\`/`X:/`、`\\host\` 开头），URL 不误报（实测 `https://…` 通过）。
- 一轮的定义：一轮 = 一次状态迁移；脚本为让那次迁移可证明而做的读（取字节正文、确认落状态）
  属于同一轮。§1.1 / §7.4 / Gotchas / AGENTS.md / `references/manual-node.md` 同步。
- `report_completion` 语义改写为 hub 真实行为（`status IN ('delivered','acked','running')`
  才改任务行；第二次 report 不改任务行但会再插一行 `completions`）。
- 200 字符预览的说法收窄成实测：摘要行 + `file:/seg:/sha12:` 在 200 内（约到第 95 字符）。
- 脚本：新增 `guard --body`（compose 与测试共用同一份规则，测试里的重复模式删掉）；
  计数全部交给 python；`die()` 不再把退出码打进消息；新增 `--summary-max`；`usage()` 打整个头部。
- 证据台账：新增 `raw/2026-11-07T201812Z-bca66563c29c.json`（pipeline 报告）与
  `raw/2026-11-07T201902Z-f26e338e0150.log`（同一次运行叙述，60 passed / 0 failed）；
  新增 `wiki/patterns/portable-protocol-content.md`；两条旧 pattern 的 Evidence 写清各自
  证据只覆盖"spec 形状校验"；`wiki/skill-impact.md` 追加 amendment 说明旧分数是人工传入。
