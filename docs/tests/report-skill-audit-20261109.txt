## 3. 正文预算：真实上限与结论

hub 侧实测（file:line，全部读源码）：

| 面 | hub 真实上限 | skill 现行预算 |
|---|---|---|
| `send_task.task` → `tasks.content` | **10 000**（`server/src/shared/task-content-limit.ts:18` `TASK_CONTENT_MAX = 10_000`） | ≤300 |
| 节点卡预览 `sessions.task` | **200**，**盲切**（同文件 `:20` `SESSION_TASK_PREVIEW_MAX = 200`） | 要求第 1 行 ≤80 |
| `report_completion.result` | 存**前 4000**字符：`result.slice(0, 4000)`（`server/src/tools.ts:1592`、`1605`） | ≤400 |
| `send_reply.text` | zod **max(10000)**（`server/src/tools.ts:2485`），入库不截（`INSERT INTO inbox … content`，`:2799`） | 无明文（沿用 400 习惯） |

结论（三条，不是一条）：

1. **派工正文保持 ≤300，不建议扩大。** 卡脖子的不是 hub（10 000），是两件事：
   `report_status(status="working")` 要求工人**逐字**回传正文（`to_name+content` 精确匹配，无 task_id 分支），
   正文越长漂移概率越高，一漂就烂在 `acked`；预览只有 200 字符，第 3 行以后在节点卡上根本看不见。
   实测：4 行指针 240–280 字符，第 1 行 + `file:`/`sha12:` 行落在前 95 字符 ⇒ 关键信息都在切点之前。
2. **交付正文（`report_completion.result`）应从 ≤400 提到 ≤1200。** hub 存 4000 是实测，
   今天的 400 是习惯性收紧，工人被迫把"跑了什么/怎么验的/长报告在哪"压成一行，
   这是 Messages 页读到的东西不可读的直接原因之一。取 1200（不是 4000）：
   Dashboard 任务详体的 result 框是 `max-h-64 overflow-y-auto`（16rem，text-xs）⇒ 1200 字符 ≈ 30 行，正好在滚得完的范围。
3. **`send_reply` 的交付文本可放宽到 ≤1500**（hub 收 10 000），并要求第 1 行 ≤80 作为摘要 —— 人在线列表里只看得到前面。

预算写进 skill 时要带上这两个数（10 000 / 4000），操作员就知道"skill 的数比 hub 的数小"是**纪律**不是限制。

## 4. Dashboard 显示：现状是纯文本，markdown 会露原字符

实测渲染方式（dashboard 仓 `/vol1/1000/docker/nec8-docker/agent-network-dashboard`）：

- `app/components/TaskDetail.tsx:329` 显示 `task.content`、`:345` 显示 `task.result`，
  两处 class 都是 `whitespace-pre-wrap break-words … font-sans` ⇒ **纯文本**，不解析 markdown。
- Messages 页同样：`app/messages/page.tsx:443`、`:488`、`app/messages/inbox/page.tsx:187` 都是 `whitespace-pre-wrap`。
- Dashboard **已有** markdown 组件 `app/components/CommentMarkdown.tsx`（react-markdown + remark-gfm，
  逐元素给类，明确不用 `prose`：Tailwind v4 未装 typography 插件，`prose` 是空类）。
  它的来历正是本项目的一次投诉：评论正文按纯文本显示，`## 归因更正`、`**错误**`、反引号**全露出原字符**（#1831）。

⇒ 推论（这是本次审计最有用的那条）：**在 dashboard 改渲染之前，正文里写 markdown 会得到"更丑"的结果**
（`##`、`**`、`|---|` 全部以原字符出现）。所以分两步：

- **skill 侧（本仓可做，零依赖）**：定一套"**纯文本也干净、将来渲染 markdown 也不脏**"的版式：
  第 1 行摘要 ≤80；块与块之间空行；列表用 `- `；字段用 `key: value`（`verdict:` / `tests:` / `report:` / `commit:`）；
  **禁止**表格、`##` 标题、`**粗体**`、围栏代码块。理由逐条写进 skill 并标 file:line。
- **dashboard 侧（独立仓，走 issue → PR → 审阅 → 上游，英文）**：把 `TaskDetail` 的 `task.content` /
  `task.result` 换成现成的 `CommentMarkdown`（和 #1831 同一手法）。这一步做完，skill 才可能放开 markdown。
