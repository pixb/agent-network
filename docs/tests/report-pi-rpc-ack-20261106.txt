=== 已知坑（写进代码注释与 README）
1) 基线必须用修复前源码：新代码里 15s 的 ack 已被地板 + compaction_start 证据 + 宽限
   兜住，「旧语义必死」在新代码里不可达。在新代码里加 legacy 开关来「复现基线」
   等于让测试钉住一条生产里不该存在的路径。
2) 镜像里没有 pkill（oven/bun:1.3.10 基底）：stop_daemon 静默失效 ⇒ 多个 daemon 并存
   ⇒ 「哪个 daemon 领了任务」变随机 ⇒ 断言打在还没产日志的文件上（本次实测到的假失败）。
   现在按 PID 杀 + 轮询确认。
3) 断言字符串必须是代码真会打的句子：`grep 重发` 命中「…不重发」自我打脸；
   「观察窗」这个词代码里根本没有。
4) MCP send_task 的字段是 alias/task（不是 to_name/content），返回体里是 message_id
   （就是 task_id）。铸节点令牌的字段是 node_name（不是 alias）。
5) stub 的文本走 message_update.assistantMessageEvent.text_delta，一轮必须带
   agent_start/turn_start —— 那才是 runStarted 的证据；排队提交时没有这两个事件，
   本任务的 settled 就永远不算完成。
6) ack 之前到达的 agent_settled 是上一轮遗留的：监听器在 ack 之前不得判定完成
   （否则 queued 的任务立刻「完成」且正文为空）。
