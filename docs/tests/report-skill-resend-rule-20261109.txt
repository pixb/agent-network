## 新增的机械判据（B）

触发条件不能靠词面白名单，所以取 hub 主键的形状：**任务 id 是 uuid4**，
文件路径 / payload sha12 / 分支名 / URL 都产生不了这个形状 ⇒ "正文里点了任务 id" = 这是一次改派。
改派正文是验收要引用的文本，所以要求行必填；预算 340（不是 300），因为点一个 task id 要 36 字符
（实测 resend 正文 308 字符）。

```bash
bash scripts/anet_payload.sh guard --body "$RESEND_BODY" --kind resend   # 308 chars ≤340, accept: 在 ⇒ 收
# 同一正文去掉 accept: 行 ⇒ 拒，并说明"验收没有可引用的要求行"
```

E2E 实测输出（`tests/manual_node_e2e.sh`，用 hub 真返回的 task id）：

```
== a timeout resend must carry a requirement line (§7.5)
   resend body (quotes task b321d71b-c201-43b7-8cb8-7d5630916639, 308 chars ≤ 340): accepted
   the same body with the requirement line removed: refused
```

新 golden 判据：`guard-requires-a-requirement-line-in-a-resend-body`（同一段正文，带 accept 收、删掉拒）。

## 自测踩到的坑（测试写错，不是规则错）

第一版负向断言用 `${BODY%accept*}` 删要求行：`%` 删的是**最短**匹配后缀，
结果正文里留下 `…; accept: every item on the segment ` ⇒ guard 回 "body ok" ⇒ 断言 RED。
改成显式 `sed 's/; accept: every item on the segment acceptance list//'` 后 E2E 全绿。
（同类坑本轮第三次：前两次是合成正文没有换行、判据在测自己的数据；判据写成 heredoc 在 `sh -c` 下引号不平衡。）
