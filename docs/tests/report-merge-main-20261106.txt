## 3. Playwright：浏览器到手了，spec 的前提是错的（已修）

headless shell 走代理下载后解压到 `~/.cache/ms-playwright/chromium_headless_shell-1217`，
本机直接可跑：`chrome-headless-shell --version` = Google Chrome for Testing 147.0.7727.15。

跑 `tests/e2e-chatpane-viewport-fit.spec.ts` 两次全红，页面快照给出真相：

    快照内容 = "Spin up your first agent" + npx --yes @sleep2agi/agent-network init

⇒ 断言的 `[data-testid="chat-pane"]` 从来没挂载：这是**空页面**，不是布局 bug。

三条实测根因：

1. **`page.route` 拦不到**：dashboard 读 hub 走服务端代理（`app/api/hub/*/route.ts` 里
   `hubFetch(COMMHUB_URL)`，RSC/server-route 侧发起）。浏览器侧一条 `/api/hub/*` 请求都没有
   （debug 跑的 `page.on('response')` 一条 [resp] 都没打出来）。
2. 计划 B 的 scope：`useNetworkId()` 先解析 network_id（sessionStorage，否则 GET
   `/api/hub/networks` 自动选一个），`useSessions/useNodes` 在 `ready && networkId` 之前不发请求。
3. 端口假设有据：本机 3000/3100 被别的容器占着（`pixbbs-mcp` 在 3100，回的就是
   `Cannot GET /nodes`；`homarr` 占 3000），3200 是现网 dashboard。spec 默认 BASE=3100
   打的正是 pixbbs-mcp。
4. 还有一个我自己的错：spec 里写了 `node-list-scroll` —— 代码里没有这个 testid，
   真实的是 `node-list-rail`。凭想象写选择器，测出来的绿就没有意义。

已落地（dashboard pixb `18015c3`）：

- 选择器按真实 DOM 修正；`E2E_LIVE_HUB=1` 时不做任何路由拦截；
- 缺 live hub 时整组**显式 skip 并写明原因**（现在跑出来是 `2 skipped`，不再是假红/假绿）；
- `playwright.e2e.config.ts`：dev 服务器固定 3199，`TEST_URL` 与 spec 共用。

要拿到真绿，需要 live hub 夹具（≥1 network、≥1 session、够溢出的 tasks、dashboard 侧登录），
即 `tests/inbox-e2e/` 那套「真 hub + 真 dashboard」的 Docker 形状加上 Playwright 容器；
代理现在 1.7 MB/s，拉 mcr playwright 镜像可行。
